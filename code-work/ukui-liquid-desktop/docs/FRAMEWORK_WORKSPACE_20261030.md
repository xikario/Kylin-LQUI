- 只对命中的主进程读取 smaps_rollup；显示 CPU 与 PSS MiB，悬停列出 PID、RSS、PSS 与 SwapPSS。PSS 分摊共享页；换出量不能忽略。CLI 子任务、WebEngine 子进程不混入主进程值，也不声称这是全框架总内存。
- CPU 单核 100%，多核可超过 100%；首次采样显示未知，不伪造 0。退出/复用 PID、其他用户进程不匹配；僵尸进程排除。按需程序显示“按需启动”，不当作故障。任务栏实际加载的 Liquid 插件也会核对。
- 状态表示“进程存在/暂停/I/O 等待”，不是完整业务健康承诺。无权限读取内存时显示未知。
- Fences → 系统监视器增加“显示 Liquid 框架进程与内存”开关，默认开启，可保存并在重启后恢复；关闭时恢复资源概况。隐藏/覆盖时沿用原采样减频策略。
- 设置、快照复制与导出都已接入。温度/带宽/日期组合圈和左右小球未涉及此次改动。

## 当前登录与正式直进方案

本机实测 `org.ukui.session.required-components filemanager` 仍是 `peony-desktop`，Fences 是 `~/.config/autostart/ukui-fences.desktop` 的应用自启。当前仍可能先看到原生桌面再看到 Fences；上次 15 秒接管试验没有改登录方式。本轮设置页会明确显示实际必需桌面组件，避免把“试运行成功”理解为“已经永久替换”。

核对了 [UKUI 官方 modulemanager.cpp](https://github.com/ukui/ukui-session-manager/blob/Debian/ukui-session/modulemanager.cpp)：上游通过 required-components 选择桌面组件，某些版本只从 `/usr/share/applications` 与 `/etc/xdg/autostart` 查找必需组件；桌面就绪通知还使用历史标识 `peony-qt-desktop`。本机有发行版补丁，不能把上游代码完全等同于本机行为。因此，仅禁用 Peony 自启或把 Fences 延迟设为 0 不构成可靠直进方案。

正式路线：

1. 提供独立的 `Fences 桌面会话` 启动项，并保留现有 UKUI 登录选项作为备用。保持 KWin、输入引擎、设置守护、托盘/通知等基础服务。
2. 用桌面 provider 在必需组件阶段启动 Fences，确认 D-Bus 所有者、真实桌面表面及绘制就绪，再通知会话管理器。
3. 同一会话只启动一次 Fences，避免 provider 与旧自启重复；原生 Peony 桌面按需回退，普通文件管理器仍可使用。
4. 故障恢复必须覆盖 Fences 启动失败、早退、隐藏、卡住和 provider 自身失败；恢复程序不能与故障进程共用唯一生命周期。保留现有“恢复原生桌面服务”启动入口。
5. 用独立测试用户/嵌套显示先验收，再做一次完整注销→登录，检查冷启动、锁屏、睡眠恢复、双屏与文件管理器。以实际登录结果确认不会闪现原生桌面。

本轮未更改必需组件、未强制注销或重启；永久直进尚未启用。当前可用的是已通过隔离测试和本机短时试验的 60 秒接管/自动恢复。下一阶段应以“单独登录选项 + 自动回退”落地，避免用隐藏窗口冒充资源释放。

## 建议的优化顺序

1. **版本和回退统一**：把 Fences/开始菜单也改成与 AI 小站类似的版本目录安装，统一记录源码提交、dirty 状态和可恢复包。
2. **采样预算统一**：本轮框架表已复用系统监视进程扫描；下一步让今日应用记录也复用带时间戳的进程快照，同时保留各自采样间隔。
3. **SDK 与构建产物分层**：明确区分源码、dependencies、build、releases、运行数据，减少清理时误删依赖的风险。
4. **共享层有版本**：对输入法/AI 空间的材质和弹窗副本先做 DPI、键盘与像素回归，再归并共享依赖；不强行覆盖。
5. **资源预算按 PSS+SwapPSS 看趋势**：先量化壁纸解码和缓存、WebEngine/CLI 子进程；避免仅根据刚启动的 RSS 或已换出的 PSS 宣称节省。
