# 输出处理通道与底层静音状态修复

2026-11-03，ARM64 实机。

## 现象与证据

用户报告拔下耳机后扬声器无声。检查时物理输出已切到
`analog-output-speaker`，但物理 sink 为静音，默认回声消除 sink 未静音，
两者音量均为 46%。仅解除物理输出静音后，用户确认声音恢复；随后再次
插拔耳机，用户确认声音正常，状态记录也显示耳机、扬声器端口正常切换，
两层均未静音。最初触发物理静音的来源未能在这次重复操作中复现，不能
据此归因于硬件、PulseAudio 或 OEM 托盘。

## 修复

- 输出状态沿 `device.master_device` 链计算有效静音，保留本层静音状态。
- 显式取消静音时解除经过验证的整条输出链静音；开启静音仅作用于所选通道。
- 用户将音量滑条调至非零时，设置音量并解除该输出链静音，操作绑定同一
  已解析设备 ID；调至零不自动解除静音。
- 缺失或循环的处理链不猜测目标。读取、轮询、热插拔通知不自动修改静音，
  麦克风、默认设备、应用流路由和回声消除模块保持原有行为。
- 音量和静音确认只读取音频，避免等待网络等慢服务。

## 验证与部署

- 完整控制中心测试 89 项通过，含四项新回归：链路有效静音、取消静音、
  非零滑条恢复与零音量保留、缺失/循环链拒绝写入。
- 独立 PulseAudio + Xvfb：主页和声音页四次点击/拖动试听均成功；
  真实 remap sink / master 静音不一致场景，两页各验证按钮取消静音和滑条恢复。
  所有测试只使用虚拟设备，不加载硬件模块或录制真实麦克风。
- 热插拔集成测试通过：输出插入 192 ms、移除 157 ms；当前页面、玻璃材质、
  监听器恢复、隐藏时停止监听等既有行为保留。
- 原子安装并重启控制中心，重启前后的音频设置一致；安装源码与仓库一致。
  本次没有重启面板或 AI 小站，也没有重启整机。
