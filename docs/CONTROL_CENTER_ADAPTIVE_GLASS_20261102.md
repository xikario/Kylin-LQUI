# 控制中心自适应烟色玻璃试用（2026-11-02）

用户同意试用“白底减弱厚亮边、暗底保留现有光泽、单张卡片压缩黑白反差”的方案。本次仅控制中心启用，没有切换文字颜色，也没有更新 AI 小站、任务栏或桌面组件。

## 实现

- 每张卡片生成缓存时，从已模糊的背景取固定 16×16 样本，估算平均亮度和亮区域占比。低亮背景保持原材质；亮区域逐渐增加时平滑进入烟色玻璃，整张卡共用一个调整量。
- 亮背景改用约 1 个逻辑像素的方向高光和细小内反光，折射主要留在窄边缘。以均值为中心压缩局部明暗，保留背景颜色和纹理；没有生硬截断亮度。
- 自适应层包含文字阅读所需的底色，C ABI 桥按调整量减去原来的额外暗化层，避免再次产生宽亮边。CPU 回退使用同样的色调与透明覆盖，边缘光线为近似实现。
- `NativeGlass(adaptive_smoke=True)` 只在控制中心创建背景时传入。原 C ABI 仍兼容，其他调用方默认关闭该模式；旧版桥缺少新接口时继续使用原材质。
- 计算只在卡片缓存生成时进行，动画和鼠标移动期间不追加渲染或定时采样。现有缓存、隐形预热及整窗补画保留。

## 验证

60 项控制功能测试、7 项映射窗口/动画测试、5 项 GPU 材质测试和 5 项 CPU 材质测试均通过。材质测试覆盖 1、1.5、2 倍 DPR、白底高光宽度和阅读底色、暗底像素不变、黑白反差压缩、颜色纹理保留、缓存复用和多个 context 之间的模式隔离。

分别在独立进程加载旧桥及新桥验证默认行为：白、黑及黑白背景的非自适应输出逐像素相同。不能将两个版本的静态 C++ 渲染器同时加载到一个进程作版本对比，GNU unique 符号会使 GL 后端相互复用。

360×240 合成卡片的代表性读数（0–255 灰度亮度，不是 WCAG 线性亮度）：纯白中心 96→82；半白半黑卡片两端 96/0→97/41；暗色样本输出逐像素不变。数据只用于验证，真实观感以对照图和实际背景为准。
