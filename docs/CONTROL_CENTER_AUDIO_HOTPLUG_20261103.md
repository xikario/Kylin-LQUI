# 声音页实时设备更新（2026-11-03）

用户反馈拔出耳机后，需要返回再进入声音页才能看到新接口名称。前一轮修正了接口命名，但仍依赖 2.5 秒轮询；输出设备读取还受整组系统服务 snapshot 完成时间影响。

## 修改

- 新增可见期间的 `pactl subscribe` 异步监听，统一 C locale，只处理 sink/source/card/server 的增删改通知。90 ms 短时间合并事件；忽略 client、sink-input 和 source-output，避免查询本身形成刷新循环。
- 事件触发独立输出读取；声音页同时独立读取麦克风，不等待网络等服务。保留原定时刷新作兜底，并让声音页的兜底音频读取同样独立于总 snapshot。
- 事件使旧版本数据失效；读取期间再次收到事件会排队补读最新结果。音量/静音操作期间等待操作结束再读，旧结果不会覆盖新状态。
- 只更新现有设备行、标题、选中标识和滑条，不重建声音页或玻璃缓存。动画中仍按原策略延迟应用到完整画面。
- 隐形预加载不启动订阅，面板关闭时终止订阅、清空待刷新标记。订阅意外退出后仅在可见时重试；恢复后读取当前状态。关闭动画中重新打开也恢复监听。
- 安装清单包含新模块，运行状态暴露监听/独立音频读取状态以便验证。

## 验证

70 项回归测试通过，包括碎片事件解析与合并、慢 snapshot 不阻塞声音页更新、读到一半再次插拔、用户动作后确认状态、隐藏时停止监听等。

端到端测试通过独立 D-Bus/PulseAudio 和虚拟 sink/source 运行，不加载硬件模块，不录音。停留在声音页并关闭定时轮询，验证设备出现/消失、默认设备切换、连续变化只保留最新状态，及隐藏后零额外音频查询。本轮增删更新耗时 171–180 ms；杀掉订阅进程后约 1.6 秒恢复。测试还检查关闭动画中反向打开时订阅恢复。耗时来自隔离环境，实际物理插孔的上报速度取决于驱动，未人工插拔用户耳机。

已安装并仅重启控制中心。安装文件与测试源哈希一致；实际运行声音页确认订阅运行，关闭后确认停止。音频默认设备、音量和静音状态前后相同。详情见 `docs/evidence/20261103-audio-hotplug/verification.json`。
