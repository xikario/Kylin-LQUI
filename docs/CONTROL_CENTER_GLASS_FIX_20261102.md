# 2026-11-02 快捷设置静止玻璃与设备列表修复

用户录屏 `vokoscreen-2026-11-02_08-59-10.mp4` 中，快捷设置停稳后显示灰蓝实底，回收途中才出现玻璃；Wi-Fi 长列表初次进入也显示不全，滚动后材质才改变。本轮已复现、修复并更新用户级安装。

## 原因

1. **异步材质就绪没有完整刷新实际窗口。** 原来只对子卡片调用 `update()`，透明窗口的子控件背景仍可能保留回退图像。尤其材质在展开动画中完成时，只更新当时原生裁切区域内的部分，动画解除裁切后也没有完整失效。移动、回收或强制抓取 QWidget 会触发重新绘制，使错误暂时消失。
2. **设备列表把整张玻璃撑出截图区域。** 原生桥要求完整卡片处于准备好的场景范围内。Wi-Fi/蓝牙条目增多后，卡片超出区域，渲染返回空图而退回实底；滚动改变卡片位置，还会使材质在成功和失败间切换。旧 Wi-Fi 页面同时把高级设置放在长内容末尾。
3. **初始场景没有覆盖所有导航位置。** 从较矮的日历返回主页，或某些入口位置导致高、矮页面分别位于入口两侧，可能超出最初的截图区域。

## 修改

- 材质就绪时使整个透明窗口重绘；展开动画结束时再次完整重绘，覆盖材质在动画前、中、后完成的时序。
- Wi-Fi、蓝牙改为固定玻璃表面内滚动设备行；Wi-Fi 开关、刷新及高级设置固定可见，滚动条加宽。轮询保留现有条目和滚动位置。
- 在窗口首次显示前捕获所有页面目标矩形的并集；内部导航继续复用原窗口和材质，不隐藏窗口或截图自身。
- 不改变光学着色器、读写系统开关的逻辑、用户配置或其他组件的运行进程。

## 验证与旧验证的盲点

旧验证的 `materialBackend=snell-gpu` 只能说明某次原生渲染使用了 GPU。`QWidget.grab()` 会强制重绘，因此不能证明用户看到的稳定画面正确。

新增验证先从真实 X11 屏幕采样，再用 QWidget 完整重绘生成对照。旧版正常展开的主页测试失败，**81.28%** 的卡片采样点存在明显差异。修复第一阶段在实际系统后端上又检出动画结束缺少重绘的分支，补齐后复验通过。
