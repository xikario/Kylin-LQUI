# 耳机插入后的声音面板标识（2026-11-03）

> 本页保留最初只读路由验证范围。后续实时热插拔与用户确认的播放演示见 [热插拔](CONTROL_CENTER_AUDIO_HOTPLUG_20261103.md)、[试听复查](CONTROL_CENTER_VOLUME_FEEDBACK_RECHECK_20261103.md)。

## 问题与确认

用户插入耳机后，声音面板仍将输出和输入列为“内置音频 立体声”，并把回声消除虚拟通道列成同样的设备名。

只读检查 PulseAudio 后确认：物理输出的 Active Port 为 analog-output-headphones，物理输入为 analog-input-mic；默认输出与输入分别经过回声消除通道，其 device.master_device 指向对应物理设备。输出 57%、输入 100%，均未静音。系统已切换接口，面板遗漏了接口及虚拟通道关系。仅据接口状态不推断耳机麦克风的实际拾音质量。

## 修改

- 后端从已有 sinks/sources 输出读取 Active Port，保留原 ID、原始描述、默认设备、音量和静音语义，不增加写操作或额外设备枚举命令。
- 虚拟通道沿 device.master_device 查找物理接口，支持链式处理和逆序枚举。缺失或循环引用显示无法确认物理设备，不猜测耳机状态。
- 设备行显示有线耳机/扬声器/外接麦克风等当前接口，副标题保留声卡名称并注明直接输入/输出或同一设备的处理通道。当前选择仍对应真实默认 sink/source ID。
- 声音页面标题同步当前接口；相同设备 ID 插拔后更新原有行，保留选择、音量和滚动布局。长名称与副标题可换行，显示文本按纯文本处理。

## 验证与部署

- 完整 64 项 UI/后端测试通过；统一字段解析后的 19 项后端测试通过。
- 新增模拟耳机→扬声器端口变化、回声消除继承物理接口、链式/缺失/循环设备引用、空字段解析、同 ID 行和标题更新无音频写操作测试。
- 独立 D-Bus/PulseAudio，仅加载虚拟设备，验证既有音量、静音、默认输入输出、应用流迁移、内部处理流与监听源保护，以及设备移除后拒绝操作。未使用实际麦克风录音。
- 真机只读设备预览和安装后实际声音页面核对通过，副标题没有裁切。自适应玻璃及原页面动画保持启用。
- 已安装并仅重启控制中心，前后音频默认设备、音量、静音状态相同；安装文件哈希与测试源一致。当前显示有线耳机（回声消除）57%、外接麦克风（回声消除）100%。
