# 2026-11-02 首次展开玻璃、动画停顿和 Wi-Fi 自动扫描

根据用户第二段录屏 `vokoscreen-2026-11-02_09-46-28.mp4` 修正。前一轮修复了停稳后的画面，但未覆盖首次展开全过程；本轮已对真实首次展开的中间帧和完整录屏重新验收，并更新本机。

## 首次展开

原路径先显示回退底板并启动动画，后台完成场景准备后，第一次 GPU 上传、卡片渲染又发生在动画帧内。旧版三轮 Qt 测试驱动的测量中，最大帧间隔约 108、183、200 ms。不能把“动画结束后是 GPU 材质”当作“整个展开过程都正确”。

现在在透明、不可见的准备阶段完成背景处理和卡片缓存，再启动展开。逐张准备之间交还事件循环，准备期间重复点击或失焦可以取消；过期后台结果不能重新打开窗口。去掉了仅用于过渡的重复 CPU 模糊。

进一步处理两处细节：

- 分数缩放下保留窗口管理器已稳定的宽度，避免 389/390 逻辑像素间反复调整，重复生成两套材质。
- 准备期间不让零散子控件绘制抢先生成材质；在透明度仍为零时先解除原生裁切并完整绘制，然后才进入裁切动画。仅检查缓存命中会漏掉背景未写入窗口缓存的问题，本轮真实录屏发现并补齐了该分支。

动画期间暂存后台快照的界面更新，停稳后统一应用，避免中途改变布局。无新增常驻渲染循环；隐藏后取消准备计时器并释放场景，保留原来的空闲退出行为。

## Wi-Fi 箭头自动扫描

此前进入详情只读 NetworkManager 的已有 AP 列表，没有请求新扫描。现在每次进入 Wi-Fi 页，在无线可用且已开启时自动扫描，并显示“正在查找 Wi-Fi 网络…”。首次系统状态尚未返回时等待该状态；退出页面后不补发扫描，也不自动开启关闭的无线设备。

`RequestScan` 成功仅表示收到请求。后台现在等待 `LastScan` 扫描完成代次更新，再返回新列表；不再马上把旧列表当作扫描结果。完成等待有 12 秒期限，近期已完成的扫描继续复用，已有扫描进行中时等待其完成。扫描只返回 Wi-Fi 域，避免重复读取所有系统服务；原有域版本保护防止旧轮询覆盖新结果。

## 验证

- 36 项控制中心与后端测试通过，包括每次箭头进入自动扫描、轮询不重复扫描、首次读取竞态、关闭无线不自动启用、扫描完成后才发布、近期扫描复用和超时，以及准备期间取消。
- 6 项真实映射窗口测试通过。新增在首次展开到约 30% 时暂停，先读取真实屏幕，再生成完整重绘对照，避免先抓取控件掩盖问题；同时保留长列表、内部导航、日历入口和减少动态效果等回归。
- 最终安装版在 `:0`、DPR 1.5 下录制 60 fps 视频，检查首次展开、收回、再次展开及真实 XTest 点击 Wi-Fi 箭头。动画期间材质构建增量为零，原生渲染空图为零；逐帧查看确认首轮展开中间画面已有玻璃。
