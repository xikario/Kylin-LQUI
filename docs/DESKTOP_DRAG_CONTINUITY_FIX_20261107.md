# 桌面拖动连续性与黑框修复（2026-11-07）

用户录屏 `vokoscreen-2026-11-07_21-29-20.mp4` 说明上轮落格与阴影修复不足。上轮测试主要比较松手后稳定画面，未覆盖拾取、跟随和落格之间的连续反馈。

## 确认的问题与实现

- 桌面选中状态会填充整个图标控件，包含图标和文字外的空白区域；液态壁纸取色较暗时呈现明显黑框。现仅保留图标轮廓和紧贴文字的选中底色。
- 点击的 ping 扩散层用壁纸取色覆盖图标，深色壁纸下形成黑块；桌面图标的扩散改为淡色光圈，保留点击缩放，进入拖动时停止点击动画。分区内部原有点击效果保留。桌面悬停缩放仍关闭。
- 原生 QDrag 的图像强制以中心为热点，改变了用户实际抓取点。桌面内单选图标现在直接移动同一子控件，使用全局鼠标位移，持续保持抓取点；不创建额外的合成器拖动窗口。
- 蓝色细线提示最近可用落点；提交后用 140 ms OutCubic 归位，布局保存最终位置，定时对账不截断动画。减弱动效时立即定位。Esc 返回原位置且不提交布局。
- 跨应用、进入分区/文件夹/回收站、按 Ctrl 复制和多选仍使用原生文件拖放。原生拖动热点同样保留抓取点；启动和切换时抑制旧源图标重复绘制。已有文件操作语义保持。

设计参考：[Apple Drag and Drop](https://developer.apple.com/design/human-interface-guidelines/drag-and-drop)、[Designing Fluid Interfaces](https://developer.apple.com/videos/play/wwdc2018/803/)。采用的是抓取点保持、连续直接反馈和短促归位原则，不依赖 macOS API，也不声称复刻其内部实现。

## 验证

8 项相关 CTest 通过：1 / 1.5 倍缩放的桌面落格与连续拖动、分区排序、图标重绘，以及真实 Peony 跨窗口拖放和文件夹操作撤回。

连续手势测试以 XTest 输入真实鼠标事件，检查偏心抓取、整段跟随、没有原生拖动小窗口、至少两个落格中间位置、准确终点、没有整格深色底、点击不盖住图标、Esc 取消、保存位置与文件内容保持。捕捉到的图像在手势结束后才编码，避免 PNG 压缩阻塞被测 UI。

另在私有 Xvfb / D-Bus / UKUI KWin 合成器下，使用用户同一壁纸串行录制验证。该次获得 134 个手势采样点、7 个归位中间位置；系统指针与 Qt 已处理位置之间最大曼哈顿距离 12 逻辑像素。这包含输入排队及采集干扰，不等价于显示延迟指标。与其他回归并行录制时曾出现 16 像素并触发时序检查失败，故最终时序验证单独运行。60 fps 是录制采样率，并非产品渲染帧率保证。
